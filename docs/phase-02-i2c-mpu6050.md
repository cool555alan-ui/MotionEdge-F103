# Phase 2：I²C 与 MPU6050

## 阶段目标

本阶段在第一阶段固件基础上加入 I²C 总线扫描、MPU6050 身份识别和六轴原始数据读取。
实现保持 HAL 调用只存在于 BSP，并使用主机模拟总线验证与硬件无关的逻辑。

## 分层与依赖

```text
App/app_main.c
    ├── Services/i2c_scanner
    ├── Devices/mpu6050
    └── BSP/bsp_i2c
            └── CubeMX I²C1 handle / STM32 HAL
```

- `BSP/bsp_i2c` 封装 `hi2c1`、7 位地址转换、超时和 HAL 状态码。
- `Services/i2c_scanner` 通过探测函数注入检查地址，不依赖 HAL。
- `Devices/mpu6050` 通过寄存器读写函数注入访问总线，不包含 STM32 头文件。
- `App/app_main` 负责扫描编排、日志、状态降级和周期采样。

CubeMX 继续负责 PB6/PB7 和 I²C1 的 100 kHz 初始化；本阶段没有修改 `.ioc`、生成的
I²C 初始化代码、启动文件或链接脚本。

## I²C 扫描

扫描地址范围为 `0x08` 至 `0x77`。`App_RunOnce()` 每次只探测一个地址，每次 HAL
探测使用一次尝试和 2 ms 有限超时，因此不存在扫描整个地址空间的长阻塞循环。

发现设备时输出地址。扫描结束后输出响应设备总数，并优先记录标准 MPU6050 地址
`0x68` 或 `0x69`。

## MPU6050 工作流

1. 扫描发现 `0x68` 或 `0x69`。
2. 读取 `WHO_AM_I` 寄存器 `0x75`。
3. 校验身份位是否符合 MPU6050 的 `0x68` 标识。
4. 向 `PWR_MGMT_1` 寄存器 `0x6B` 写入 `0x00` 退出睡眠。
5. 每 100 ms 从 `ACCEL_XOUT_H` 开始读取连续 14 字节。
6. 按大端有符号 16 位数解析加速度 XYZ 和陀螺仪 XYZ，温度字段暂不使用。

设备缺失、身份错误、唤醒失败或采样失败会使应用进入 `DEGRADED` 状态，而不是阻止
LED 心跳和健康统计继续运行。采样失败后停止周期读取，避免持续错误日志占用串口。

## 软件验证

Windows 主机测试使用内存中的模拟总线，覆盖：

- 扫描器空指针、未初始化状态、完整地址范围、响应计数和完成状态；
- MPU6050 参数检查、合法地址、总线失败；
- `WHO_AM_I` 读取和身份错误；
- 唤醒寄存器地址和值；
- 正数、负数和 16 位边界值的六轴原始数据解析。

STM32 Debug 构建验证 BSP 与 CubeMX `hi2c1`、HAL I²C API 和用户 CMake 源码的集成。

## 待硬件验证

- PB6/PB7 外部上拉、电平和接线；
- I²C 扫描能否发现实际模块；
- 模块地址是 `0x68` 还是 `0x69`；
- 实际 `WHO_AM_I` 响应；
- 唤醒后的六轴原始数据是否随姿态和运动变化；
- 串口日志、烧录和 ST-LINK 调试。

没有连接硬件前，不把这些项目描述为已经实机通过。
